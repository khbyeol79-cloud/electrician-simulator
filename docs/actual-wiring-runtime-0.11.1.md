# 0.11.1 실제 결선 기반 동작 엔진

## 적용 범위

0.11.1은 0.11.0의 공통 기구 동작 카탈로그를 실행 시점의 회로 정의에 연결한다. 저장된 문제 JSON과 자유회로 작업공간을 직접 변환하지 않고 `DeviceBehaviorRuntimeComposer`가 런타임 복사본에 누락된 단자·코일·접점·기구 내부 연결을 병합한다.

현재 자체제작 자유회로 3종과 과거 저장 작업공간은 `legacy_assisted` 기본값을 유지한다. `actual_wiring`은 명시적으로 선택한 새 회로 정의에서만 사용한다. 따라서 0.11.0 사용자의 결선과 SQLite 데이터가 자동 변환되거나 손상되지 않는다.

## 계산 모드

| 모드 | 용도 | 전기적 인터록 | EOCR | 모터 방향 |
| --- | --- | --- | --- | --- |
| `legacy_assisted` | 기존 문제·저장 작업공간 호환 | 메타데이터로 동시 여자 차단 | 보호 대상 코일 직접 차단 | 기존 정·역 역할과 상 순서 사용 |
| `actual_wiring` | 새 자유회로와 엔진 검증 | 실제 NC 보조접점의 도통 경로 | 실제 95-96·97-98 접점 | L1·L2·L3에서 U·V·W까지 실제 상 순서 |

기계적 인터록은 전기 접점이 아니므로 두 모드 모두 접촉기 사이의 물리 관계 메타데이터로 처리한다.

## 런타임 구성 경계

런타임 구성기는 다음을 수행한다.

- `CircuitDevice.behavior_model_id`의 명시적 카탈로그 모델 확인
- 과거 형식 actual-wiring 정의에 대한 제한된 서버 소유 호환 매핑
- 단자·코일·접점 ID 중복 검사
- 기존 정의와 카탈로그 정의가 다를 때 조용히 덮어쓰지 않고 오류 처리
- EOCR 보호접점과 `OperationProtectionDevice` 연결
- MCCB·퓨즈·EOCR 정상 상태 고유 연결 병합
- 입력 정의와 사용자 전선을 제자리에서 수정하지 않는 깊은 복사
- 같은 입력을 반복 구성해도 결과가 같은 결정적·멱등적 처리

문제 답안, `expected_nets`, 승인 여부는 이 구성 경로에 전달되지 않는다.

## 실제 접점 계산

### 전자접촉기 교육용 모델

현재 `magnetic_contactor_12p_training`은 프로젝트 기능검증용 `unverified` 모델이다.

- 주접점: `1-7`, `2-8`, `3-9`
- 자기유지 NO: `4-10`
- 인터록 NC: `5-11`
- 코일: `6-12`

코일 무여자 시 주접점과 자기유지 접점은 열리고 인터록 접점은 닫힌다. 코일 여자 시 반대로 바뀐다. 이 번호를 모든 제조사 또는 Q-Net 공식 규격으로 단정하지 않는다.

### EOCR 교육용 모델

현재 `eocr_12p_training` 역시 `unverified` 모델이다.

- 정상: `95-96` 닫힘, `97-98` 열림
- 트립: `95-96` 열림, `97-98` 닫힘
- 정상 상태 주회로: `L1-U`, `L2-V`, `L3-W`

actual-wiring에서는 95-96을 실제 코일 회로에 직렬 연결한 경우에만 트립으로 코일이 복귀한다. 해당 접점을 우회하면 엔진은 코일을 강제로 끄지 않고 `protection_bypassed` 위험을 표시한다.

## 실제 상 순서 판정

actual-wiring의 모터 방향은 접촉기 이름이나 `forward_coil_id`만으로 결정하지 않는다.

1. 현재 닫힌 접점과 사용자 전선으로 도통 그래프를 만든다.
2. 각 모터 U·V·W 단자가 어느 phase source에 연결되는지 찾는다.
3. 세 단자에 서로 다른 세 상이 하나씩 도달하면 순열 parity로 정·역회전을 판단한다.
4. 한 상이 없으면 `phase_loss`, 한 단자에 둘 이상의 상이 연결되면 `connection_error`, 직접 상간 경로는 `phase_short`로 처리한다.

## 사용자가 바로 실행할 간단 시험

프로젝트 폴더에서 다음을 실행한다.

### Windows PowerShell

```powershell
.\.venv\Scripts\python.exe scripts\run_actual_wiring_demo.py
```

### 개발용 Linux 셸

```bash
.venv/bin/python scripts/run_actual_wiring_demo.py
```

이 스크립트는 정답 데이터 없이 다음을 자동 확인한다.

- START와 MC 자기유지
- STOP과 주접점 개방
- 정상 상 순서 정회전
- 두 상 교환 역회전
- 한 상 누락 결상
- EOCR 95-96 직렬 보호
- EOCR 97-98 경보 표시등
- EOCR 접점 우회 시 실제 운전 지속과 위험 진단

## 시험용 단자 결선표

이 결선은 0.11.1 엔진 기능검증용 자체제작 예시이며 Q-Net 공식 답안이 아니다. 통합 기본보드 UI는 0.11.2 예정이므로 이번 버전에서는 위 스크립트가 동일 결선을 자동 구성한다.

### 제어회로

| 번호 | 시작 단자 | 도착 단자 | 목적 |
| ---: | --- | --- | --- |

## 수동 변형 시험

| 시험 | 결선 변경 | 예상 결과 |
| --- | --- | --- |
| 정상 운전 | 위 19가닥 | START 후 MC1 여자·자기유지, 모터 `forward` |
| 정지 | 정상 운전 중 PB0 누름 | MC1 복귀, 주접점 개방, 모터 `stopped` |
| 역상 | PWR-L2와 PWR-L3의 MC 입력을 교환 | 모터 `reverse` |
| 결상 | MC1-9 ↔ EOCR-L3 제거 | 모터 `phase_loss` |
| 정상 보호 | 정상 운전 중 EOCR 과부하 | 95-96 개방, MC1 복귀, `protection_trip` |
| 경보 접점 | 정상 운전 중 EOCR 과부하 | 97-98 폐로, AL 경보 표시등 점등 |
| 보호 우회 | MC1-12 ↔ PWR-N 추가 후 EOCR 과부하 | MC1 운전 지속, `protection_bypassed:EOCR` 위험 |

## 제한사항

- 실제 전압, 전류, 접촉저항, 단락전류와 차단곡선을 계산하지 않는다.
- 모터 RPM, 토크, 관성과 기계적 접촉기 이동 시간을 계산하지 않는다.
- MC와 EOCR의 현재 교육용 핀 모델은 공식 근거 확인 전까지 `unverified`다.
- 기존 3개 자유회로 시작 보드는 이번 버전에서 통합하지 않는다.
- Q-Net 공식 공개문제 18개 데이터 구축·검증은 별도 단계다.
