# Q-Net 010 동작 검증 개발 인계서 0.14.0-dev6

## 구현 결과

- 신규 작업공간은 기본보드·빈보드 모두 2회로 4단자 FUSE만 생성한다. 채널은 `1-2`, `3-4`로 독립 단선 시험이 가능하다. 구형 2단자 모델은 기존 저장 데이터 로드 호환용으로만 남고 팔레트/API 신규 생성은 차단된다.
- Q-Net 010 회로도 분석은 정답 입력·제출·채점을 제거하고 사용자/문제별 개인 메모, 기구·소켓·단자 선택을 SQLite에 자동저장한다.
- Q-Net 010은 카탈로그 기구 동작을 조합한 실제 결선 엔진과 25개 공개 동작 요구사항을 사용한다. 결과는 `충족/미충족`뿐이며 점수·합격/불합격은 없다.
- EOCR은 12P 물리 핀과 95–97 내부 공통을 반영하고, 명시된 A1–A2 전원이 실제로 공급되고 보호 대상 모터가 운전 중일 때만 과부하 트립을 허용한다.
- 프런트는 NO/NC 배지, 8P 전환접점 양쪽 상태, 정확한 타이머 ms, 독립 FUSE 단선, EOCR 전원/핀 안내, 요구 동작 결과를 표시한다.
- Q-Net 보드를 고정 배치로 지정해 T1/MC1 라벨 겹침을 제거했다.

## EOCR 결선 기준

- 물리 핀: `4=96(NC 출력)`, `5=98(NO 출력)`, `6=A1`, `10=95(NC 공통)`, `11=97(NO 공통)`, `12=A2`.
- 기구 내부에서 `95-97`은 공통이다.
- 보호 전원 Net은 FUSE 출력에서 95와 A1으로 공급할 수 있으므로 `F-2→EOCR-10`, `F-2→EOCR-6` 또는 `EOCR-10→EOCR-6` 형식이 전기적으로 같은 Net을 형성한다. `EOCR-4→PB0-1`, `EOCR-5→YL-1`을 사용한다.
- 과거 사용자 후보의 4↔10, 5↔11 방향 반전은 수정된 12P 핀 의미와 보호선 Net을 충족하지 않아 정답으로 완화하지 않았다.

## 보안·데이터 보존

- 공개 setup에는 요구사항 ID/문구만 노출하며 action, expectation, 비공개 답안은 노출하지 않는다.
- 요구사항 실행은 사용자의 저장 결선과 공개 동작 정의만 사용하고 매 항목마다 격리된 새 엔진에서 실행한다.
- DB 스키마 11에 `circuit_analysis_drafts`만 추가했으며 기존 테이블/SQLite/결선/자유회로를 마이그레이션 삭제하지 않는다.
- `frontend/dist`는 직접 편집하지 않고 `frontend/src` 변경 후 Vite 빌드로 생성했다.

## 미해결 및 다음 작업

Q-Net 공식 PDF에는 FUSE 외부 단자번호 `1-2 / 3-4`가 명시되지 않는다. 사진과 실기 관행으로 기능은 구현했지만 공식 근거 부족 때문에 010은 계속 `draft/unverified`, 무채점 연습 상태다. 공식 제조사 자료 또는 Q-Net 정정 자료가 확보되기 전에는 검증 완료나 합격 판정으로 승격하지 않는다. 001~009·011~018은 이번 변경에서 기능 구현하지 않았다.

재생성은 `scripts/build_qnet_010_private_definition.py problem --write`와 `answer --write`, 준비도 확인은 `scripts/check_qnet_010_readiness.py`를 사용한다.
