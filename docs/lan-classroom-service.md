# 기관 LAN 운영 및 Raspberry Pi 이전 안내

작성일: 2026-09-20. 구현/검증 결과는 [작업 기록](lan-classroom-progress.md), 현재 공개 범위는 [최신 개발 상태](../DEVELOPMENT_STATUS.md)를 참고한다. 사용자 후보 결선이 포함된 상세 검수표는 공개 소스에서 제외했다.

## 운영 범위

- Windows 서버 PC 1대, 같은 기관 LAN의 약 20명. 외부 인터넷 공개는 이번 단계에서 하지 않는다.
- 가입 정보는 **아이디·비밀번호·닉네임만** 받는다. 가입코드·이메일·전화번호는 없다.
- 아이디: 영문/숫자/밑줄 4~24자, 대소문자 구분 없음. 가입/재설정 비밀번호: 6~128자(사용자 요청 반영). 닉네임: 2~20자. 화면 입력창의 예시 문구는 표시하지 않는다.
- `REGISTRATION_OPEN=true`가 초기값이다. 관리자 페이지에서 가입 허용을 저장하면 그 값이 우선하며 즉시 적용·재시작 후 유지된다. 기존 계정 로그인은 유지된다.
- 닉네임이 같아도 계정은 다르다. 서버가 발급한 고정 계정 ID로 회로 분석·작업공간·버전·결선·자유회로 DB를 분리한다.
- 기존 데스크톱 닉네임 DB는 자동으로 새 계정에 연결하지 않는다. 타인의 닉네임을 입력해서 기록을 가져갈 수 없도록 한 조치다. 기존 결선은 해당 사용자가 JSON을 내보낸 뒤 새 계정에서 가져온다.

## 실행 전 기관에서 정할 항목

1. 기관 관리자의 서버 운영 허가, 서버 PC의 고정/예약 LAN IP 및 허용할 교실 대역.
2. 모든 교실 PC가 신뢰할 수 있는 HTTPS 인증서와 서버 이름. **LAN이라도 HTTP는 비밀번호를 암호화하지 않는다.** 실제 비밀번호 가입 전에 기관 담당자가 HTTPS와 인증서 신뢰를 준비한다. 인증서 경고를 무시하도록 안내하지 않는다.
3. Windows 방화벽은 프로그램/포트·교실 원격 주소로 범위를 제한한다. IPv4/IPv6, 다른 NIC, 공유기 포트 전달 및 UPnP 노출 여부도 확인한다. `ALLOW_LAN`은 방화벽/접근대역 제한 기능이 아니다.
4. 서버 PC에는 학생 계정과 구분되는 운영용 OS 계정이 필요하다. 데이터·설정·TLS 개인키·백업 폴더를 학생 계정이 읽거나 수정할 수 없게 한다. 학생이 서버 PC의 관리자 권한까지 갖는 환경에서는 웹 로그인만으로 데이터를 보호할 수 없다.
5. 전원/절전/자동 재부팅 정책과 종료 시각, 백업 담당자. Windows 서비스 등록·방화벽 변경은 이 작업에서 수행하지 않았다.

## Windows 준비와 실행

프로그램 안에 `user-data/`라는 전용 폴더로 계정·학습 DB를 모은다. 코드/정적 웹 파일과는 별도이며 인터넷으로 제공하는 폴더가 아니다. 아래 설정/인증서 경로는 운영 예시이며 실제 기관 설정을 생성하거나 공개한 것은 아니다.

1. 이 프로젝트 소스, `problems/`, `catalog/`, `schemas/`, `frontend/dist/`, `scripts/`를 서버에 준비한다. private 답안·개발 테스트 파일은 공개 정적 웹 폴더에 넣지 않는다.
2. 서버용 Python 가상환경을 새로 만들고 `backend/requirements-web.txt`를 설치한다. Windows 개발 가상환경을 Pi로 복사하지 않는다. 현재 개발 검증 환경은 Python 3.12.14, Node 24.19.0이다.
3. 프런트엔드는 `frontend/`에서 `npm ci`, `npm run build`로 만든다. 생성된 `dist`를 직접 편집하지 않는다. 사전 빌드한 `dist`를 배포하면 운영 서버에서 Node를 상시 실행할 필요는 없다.
4. `deploy/lan.env.example`을 프로그램 안의 비공개 `service-config/service.env`로 복사한다(상위 폴더는 먼저 준비). 기본 `ELECTRICIAN_DATA_DIR=user-data`는 **프로그램 위치 기준 상대 경로**다. USB 드라이브 문자나 실행 터미널 위치가 달라져도 프로그램 옆 데이터를 사용한다. `APP_PORT`, `APP_HOST`는 기관 환경에 맞춘다. 기존 절대 경로 설정도 계속 지원하며 임의로 바꾸지 않는다. **설정값만 바꿔도 기존 기본 데이터가 자동 이동되지는 않는다.**
5. 프로젝트 루트에서 실행한다. 인증서/키 경로는 기관이 준비한 실제 파일로 바꾼다.

```powershell
.venv\Scripts\python.exe scripts/run_service.py --env-file service-config/service.env --cert service-config/server.crt --key service-config/server.key
```

이 실행기는 인증을 항상 켜고 디버그/자동 reload를 끈다. 직접 TLS를 사용하면 Secure 쿠키가 자동 활성화된다. 인증서 인수가 없는 HTTP 실행은 경고를 표시하며, 실제 비밀번호 없이 로컬 개발 확인에만 사용한다. 리버스 프록시를 추가할 때에는 현재의 동일 출처 검사·신뢰 프록시 설정을 따로 검증해야 한다. 현재 실행기는 임의의 forwarded 헤더를 신뢰하지 않는다.

동작시험 엔진은 서버 메모리에 있으므로 **worker 1개**로 운영한다. worker를 늘리거나 다른 서버로 요청을 분산하면 동작 세션이 공유되지 않는다. 서버 재시작 시 운전 중 상태는 초기화되지만 저장된 결선과 계정은 DB에 남는다.

## 간편 시작 · 종료 백업 · USB 복사

환경 설치와 프런트 빌드를 마친 Windows 서버 PC에서는 프로그램 폴더의 다음 파일을 사용한다.

1. **`서버_시작.bat`** 더블클릭: 기존 `service-config/service.env`와 관리자 페이지에 저장한 IP/포트로 실행한다. 설정 파일이 없을 때만 LAN 예시 파일을 최초 생성하며 기존 파일은 덮어쓰지 않는다. 서버 창은 사용 중 열어 둔다.
2. **`서버_종료_백업.bat`** 더블클릭: 학생들에게 저장 완료·로그아웃을 안내한 뒤 `Y`를 입력한다. 새 접속을 닫고 처리 중 요청과 애플리케이션 종료를 기다린 뒤 모든 계정/사용자 DB를 백업한다. 아직 브라우저에서 보내지 않은 입력은 백업할 수 없다.
3. **‘서버 종료 및 백업 완료’ 확인 → 자동으로 열린 `user-data-backups` 폴더의 최신 ZIP 하나를 USB에 복사**한다. 파일명은 `electrician-users-YYYY-MM-DD_HH-MM-SS-고유번호.zip`이다. 기존 ZIP은 삭제하거나 덮어쓰지 않는다.

최초 전환 시, 예전 명령으로 실행 중인 서버는 사용자 저장을 확인하고 **그 서버의 콘솔에서 Ctrl+C로 한 번 종료**한 뒤 새 시작 파일을 사용한다. 간편 종료 도구는 임의 PID/다른 Python/Codex 프로그램을 종료하지 않는다. 새 도구로 실행되지 않은 서버에는 종료 완료라고 표시하지 않는다. 기존 `run_service.py` 방식도 지원하지만 자동 종료 백업은 `service_launcher.py start`/시작 배치 파일에서 제공한다.

백업 완료까지 동일 데이터 폴더의 중복 시작을 막는다. 종료 요청은 서버 PC의 로컬 상태 파일로만 전달하며 인터넷/웹 종료 API는 없다. 시간이 오래 걸리면 강제 종료하지 않고 서버 창에서 진행 상태를 확인한다. 오류 또는 `.partial.zip`은 완료된 백업이 아니다. **콘솔 X 버튼·작업 관리자 강제 종료·정전 때는 백업을 보장하지 않는다.** Ctrl+C 정상 종료도 백업하지만 USB 폴더를 자동으로 여는 권장 경로는 종료 배치 파일이다.

백업에는 계정 ID·비밀번호 해시·닉네임·관리자 권한·관리 설정·학습 기록이 포함된다. 로그·프로그램 본체·env 설정·TLS 인증서는 별도 보관한다. ZIP은 암호화되지 않으므로 USB를 안전하게 관리한다. USB에 복사하기 전에 ZIP의 DB 무결성·CRC·체크섬을 검사하지만, USB 복사 완료/안전 제거는 운영자가 확인해야 한다.

TLS를 이미 사용한다면 시작 바로가기/명령에도 기존 인증서를 전달한다(예시):

```powershell
.\서버_시작.bat --cert service-config/server.crt --key service-config/server.key
```

별도 설정 파일을 사용한 경우 종료 명령에도 같은 `--env-file`을 전달한다. 기본 백업 위치는 프로그램 옆 `user-data-backups`이며 USB 드라이브 문자를 추측하지 않는다. `.venv`가 없거나 시작/백업에 실패하면 창에 오류를 남기며 성공한 것으로 처리하지 않는다.

## 학습자 사용 주의사항

- ‘저장됨’을 확인하고 화면 이동·새로고침·로그아웃한다. 같은 작업공간을 여러 PC/탭에서 동시에 수정하지 않는다. 마지막 저장이 앞선 내용을 덮어쓸 수 있다.
- 중요한 시점에는 ‘새 버전 저장’과 JSON 내보내기를 활용한다. 이번 작업은 저장 충돌 해결·오프라인 저장을 새로 구현하지 않았다.
- 공용 PC에서는 브라우저의 비밀번호 저장을 사용하지 않고, 사용 후 반드시 로그아웃한다. 창 닫기는 로그아웃을 대신하지 않는다.
- 로그인은 서버 요청이 30분 없으면 만료되고, 활동 중에도 10시간 뒤 다시 로그인한다. 계정당 동시 로그인은 최대 5개다. 비밀번호를 잊으면 운영자에게 재설정을 요청한다.
- 계정당 메모리 동작시험 세션은 최대 8개, 2시간 미사용 시 정리된다. 이 제한은 저장된 작업공간을 삭제하지 않는다.
- 웹 화면의 요구사항 ‘충족’은 구현된 시나리오의 논리 동작 확인이다. 실제 전류·절연·기계 결함 또는 시험 합격을 보증하지 않는다.

## 백업·복원과 계정 그대로 이전

프로그램 기준 데이터 구조:

```text
프로그램 폴더/
  user-data/
    accounts.db         계정 ID·닉네임·비밀번호 해시·로그인 세션
    app.db              이 저장소의 기본 사용자 데이터
    users/<계정ID>.db    계정별 분석·결선·작업공간·버전 등
    logs/               운영 로그 (데이터 백업에 포함하지 않음)
```

기본 실제 경로는 현재 개발본의 경우 `D:\project\elec\electrician-simulator-dev\user-data`다. LAN/계정 서버를 실행하면 필요한 폴더가 생성된다. 인증 없는 기존 데스크톱은 이전 저장 경로를 그대로 사용하므로, 기존 자료가 필요하면 종료 후 백업/JSON 내보내기로 별도 이전한다. 이번 변경은 기존 `data/dev`나 `%LOCALAPPDATA%/ElectricianSimulator`의 기록을 자동 이동/삭제하지 않는다.

**프로그램 종료 후 `user-data` 폴더 전체를 USB로 복사하면 계정과 모든 사용자 기록을 함께 보관할 수 있다.** `users`나 개별 DB만 옮기면 계정과 기록의 연결을 잃을 수 있다. 실행 중 DB 파일을 탐색기로 복사하거나 USB를 빼지 않는다. 복사한 폴더의 이름도 `user-data`로 유지하고, 기존 데이터 위에 병합/덮어쓰기하지 않는다. 먼저 별도 새 폴더에서 복원/로그인을 확인한다.

프로그램 전체를 가져갈 수도 있지만, 다른 PC의 Python 가상환경까지 그대로 실행된다는 뜻은 아니다. `.venv`는 대상 PC에 맞게 재설치하고 소스·빌드 버전과 데이터는 함께 보관한다. 운영은 PC 로컬 디스크에서 하고 USB는 이동/백업용으로 사용하는 편이 안전하다. USB에는 계정 해시·개인 기록이 있으므로 분실에 대비한 암호화/접근 보호가 필요하다.

권장하는 검증형 ZIP 백업도 **서비스를 먼저 정지한 뒤** 실행한다. `--server-stopped`는 운영자가 정지했음을 확인하는 인수이지 자동 정지 명령이 아니다. 아래 명령은 프로그램 폴더에서 실행하고, 예시 백업 경로의 상위 폴더는 미리 준비한다.

```powershell
.venv\Scripts\python.exe scripts/service_data.py backup user-data E:\Backups\electrician-20260920.zip --server-stopped
.venv\Scripts\python.exe scripts/service_data.py restore E:\Backups\electrician-20260920.zip restored-user-data --server-stopped
```

- SQLite backup API로 커밋된 WAL 내용까지 포함한다. DB 무결성 및 각 파일 SHA-256을 확인한다.
- 기존 ZIP은 덮어쓰지 않는다. 복원 목적지는 **아직 존재하지 않는 새 디렉터리**여야 한다. 검증 실패 시 복원본을 운영 경로로 게시하지 않는다.
- 동일 버전의 프로그램에서 복원한 뒤 `ELECTRICIAN_DATA_DIR=restored-user-data`로 새 사본을 확인한다. 새 배포 폴더에 아직 `user-data`가 없으면 처음부터 그 이름으로 복원해도 된다. 기존 원본은 확인 완료 전까지 보존한다.
- 계정 ID·비밀번호 해시·닉네임과 사용자 DB를 함께 이전하므로 **LAN에서 쓰던 아이디/비밀번호로 Pi에서도 로그인**한다. 새로 가입하거나 동일 닉네임으로 계정을 재생성하지 않는다.
- 로그인 토큰은 이전본에서 폐기하므로 새 서버에서 다시 로그인해야 한다. 원본 서버의 계정/세션은 백업·복원으로 바뀌지 않는다.
- 백업에는 원본 비밀번호가 없지만 해시와 개인 결선이 들어 있다. 도구 자체는 ZIP을 암호화하지 않는다. 외장 저장소/외부 보관소에 두기 전 별도 암호화하고, 암호키를 같은 곳에 보관하지 않는다. Google Drive 자동 업로드는 아직 구현/연결하지 않았다.
- 데이터 백업과 별개로 실행 소스/빌드 버전, 운영 설정, 인증서 갱신 방법을 보관한다. `.venv`, OS 파일, 소스, 정적 문제 자료는 데이터 ZIP에 포함되지 않는다.
- 기본 운영안: 수업 종료 후 일 1회 및 업데이트/이전 직전 백업, 정기적으로 별도 새 폴더에 복원 시험. 보관 기간은 임의로 만료시키지 않으며 용량과 기관 운영 규칙에 맞춰 운영자가 관리한다.

관리자는 **서버 관리 → 계정 목록 → 비밀번호 재설정**에서 대상 계정을 확인하고 관리자 현재 비밀번호, 새 비밀번호(6~128자), 확인을 입력한다. 관리자 비밀번호를 다시 검증하며 대상의 모든 기존 로그인 세션은 폐기한다. 기존 학습 기록·계정 ID는 바뀌지 않는다. 새 비밀번호는 사용자에게 별도로 전달한다. 관리자 본인 계정도 재설정하면 다시 로그인해야 한다. 비밀번호 원문/해시는 관리 응답·감사 이력에 기록하지 않는다. LAN HTTP는 암호화되지 않으므로 신뢰할 수 있는 HTTPS 사용 원칙은 동일하다.

관리자 자신의 비밀번호를 잊은 경우에는 서버에 접근 가능한 운영자가 기존 오프라인 CLI를 사용할 수 있다. 먼저 종료/백업하고 실행한다.

```powershell
.venv\Scripts\python.exe scripts/service_data.py reset-password user-data student01 --server-stopped
```

## Raspberry Pi 이전 준비

- 64비트 Linux/ARM64용 Python 환경을 별도로 준비한다. Windows `.venv`나 pywebview 데스크톱 런처를 가져가지 않는다. 웹용 의존성만 설치한다.
- 이식형 기본 구성은 Pi에서도 프로그램 옆 `user-data`다. 별도 Linux 서비스 디렉터리를 쓰려면 절대 경로 설정으로 바꿀 수 있다. 예: 소스 `/opt/electrician`, 데이터 `/var/lib/electrician/data`, 설정/인증서 `/etc/electrician`. 전용 비관리자 OS 계정으로 실행한다.
- 서비스 정지 → Windows 데이터 백업 → Pi의 **새 데이터 디렉터리로** 복원 → `ELECTRICIAN_DATA_DIR` 갱신 → 같은 계정 로그인/작업공간 확인 순서다. 복원 도중 기존 LAN 서버에서 새 학습 내용을 저장하지 않도록 전환 시간을 공지한다.
- `deploy/electrician.service.example`은 프로그램 내부 `/opt/electrician/user-data`만 쓰기를 허용하는 systemd 샘플이다. 실행 전에 해당 폴더를 만들고 운영 계정에 쓰기 권한을 준다. 다른 절대 데이터 경로를 쓰면 `ReadWritePaths`도 동일하게 바꾼다. 경로·운영 계정·인증서 읽기 권한·데이터 쓰기 권한을 맞춘 뒤 사용한다. 이번 작업에서 Pi 접속/설치/서비스 등록은 하지 않았다.
- 외부 도메인 공개는 별도 단계다. HTTPS, 접근 정책, 관리자 비공개 영역, 백업, 실제 Pi 부하 시험을 완료한 뒤 결정한다. 가입코드가 없으므로 외부 공개 시 누구나 가입할 수 있는지 운영 정책을 다시 정해야 한다.

## 서버 관리 페이지

상단 **서버 관리** 또는 `/admin`으로 접속한다. 지정된 관리자에게만 메뉴가 보이며, API도 매 요청마다 관리자 권한을 확인한다. 첫 가입자는 자동으로 관리자가 되지 않고, 닉네임/요청 헤더로 권한을 지정할 수도 없다. 인증 없는 기존 데스크톱/닉네임 모드에서는 관리 API를 열지 않는다.

### 처음 한 번: 관리자 지정

1. 관리에 사용할 계정을 일반 회원가입으로 만든다.
2. 서버를 종료한다. 아래 `user-data`는 **실제 서비스의 데이터 폴더**로, `my_admin_id`는 가입한 아이디로 바꾼다. 비밀번호는 명령에 쓰지 않는다.
3. 프로그램 폴더의 터미널에서 실행한다.

```powershell
.venv\Scripts\python.exe scripts/manage_admin.py user-data my_admin_id --server-stopped
```

4. `scripts/run_service.py --env-file service-config/service.env`로 서비스를 켜고 다시 로그인한다. 기존 로그인 세션은 권한 변경 시 폐기되며 학습 데이터는 그대로다. 관리자 해제는 같은 명령에 `--revoke`를 추가한다. 이 CLI는 서버의 OS 접근 권한이 있는 운영자만 실행해야 한다.

### 화면에서 할 수 있는 일

- 현재 접속 주소, 수신 주소/포트, 서버 LAN IP 후보, 가동 시간, DB 준비 상태, 디스크 여유 공간 확인.
- 신규 회원가입 즉시 열기/닫기. 가입코드 없음.
- 가입 계정·역할·유효 로그인 세션 수·세션의 최근 활동 확인. 세션 수는 실시간 동시 접속 PC 수가 아니다. 최근 활동은 최대 약 1분 단위로 갱신된다.
- 다른 계정의 전체 기기 로그아웃(확인창 제공). 다음 서버 요청부터 인증을 거부하며 저장된 학습 기록은 삭제하지 않는다.
- 관리자 비밀번호 재확인을 거친 계정 비밀번호 재설정(확인창 제공). 새 비밀번호 확인, 요청 횟수 제한, 관리자 권한/CSRF 검사를 적용한다.
- 데이터 저장 경로·USB 백업 절차, 서버 PC 실행 명령과 최근 관리 이력 확인. 비밀번호/해시/세션 토큰/개인 결선은 관리 응답에 포함하지 않는다.

### IP/포트 변경과 복구

- 전용 `run_service.py` 실행 모드에서만 다음 실행의 IP/포트를 저장할 수 있다. 직접 `uvicorn` 실행 중에는 현재 요청의 실제 로컬 소켓을 표시하고 설정 입력을 비활성화한다. 실행 옵션과 달리 적용됐다고 표시하지 않는다.
- 저장은 현재 서버를 재시작하지 않는다. 학습자의 저장을 확인한 뒤 서버 PC에서 종료·재실행한다. 네트워크 설정은 `accounts.db`에 저장되며 다음 `run_service.py` 실행 시 env 파일의 IP/포트보다 우선한다.
- 지원 IP: `127.0.0.1`, `0.0.0.0`, RFC1918 사설 IPv4. 포트: 1024~65535. IPv6, 공인 IP/호스트명, 자동 OS IP 변경, 방화벽/공유기 설정은 이번 기능에서 지원하지 않는다.
- `0.0.0.0`은 접속 주소가 아니라 모든 IPv4 인터페이스의 수신 주소다. 서버 PC의 LAN IP로 접속한다. **사설 IP 수신은 LAN 접근 제한을 보장하지 않는다.** 방화벽 허용 원격 대역과 공유기 포트 전달을 운영자가 별도로 점검한다.
- 존재하지 않는 IP/사용 중인 포트를 저장하여 시작에 실패하면, 서버를 종료한 상태에서 아래 명령으로 **저장된 네트워크 설정만** 해제한다. 계정·기록·관리자 권한·가입 허용 상태는 유지된다. 이후 env 파일의 올바른 주소로 다시 실행한다.

```powershell
.venv\Scripts\python.exe scripts/manage_admin.py user-data --clear-network --server-stopped
```

- Pi 이전 후 Windows의 고정 IP가 더 이상 유효하지 않으면 위 명령을 `.venv/bin/python`으로 실행한 뒤 Pi의 새 주소로 설정한다. 관리자 권한·서비스 설정·이력은 기존 데이터 백업 도구가 `accounts.db`와 함께 보존한다.
- 웹에서 서버 종료/재시작, 계정/학습 DB 삭제, 실행 중 일괄 백업 다운로드, 임의 파일/명령 실행은 제공하지 않는다. 서버 PC의 간편 시작/종료 파일을 사용하며, 웹에서는 지정된 관리자에게만 비밀번호 재설정을 제공한다.

## 검증 범위와 남은 운영 확인

20계정 동시 API 시험, 8시간 활동 시계 모의, 계정 분리, SQLite 백업/복원 후 같은 계정 로그인, 로컬 브라우저 가입/로그아웃/결선 동작을 확인했다. 실제 교실 20대에서 8시간 연속 사용하거나 Pi ARM64 성능·HTTPS 인증서·기관 방화벽을 시험한 것은 아니다. 기관 공개 전 실제 네트워크와 PC 환경에서 이를 확인해야 한다.

비밀번호 저장·세션·CSRF 설계 참고: [OWASP 비밀번호 저장](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [세션 관리](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html), [CSRF 방어](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html). 공개 서비스 전체에 대한 보안 인증을 의미하지 않는다.
