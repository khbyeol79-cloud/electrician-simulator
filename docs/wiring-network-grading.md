# TB 자유 선택과 전기적 네트워크 채점

0.9.0부터 결선 제출은 정답 예시의 전선 쌍을 그대로 복사했는지가 아니라, 최종적으로 어떤 기능 단자와 외부 기구선이 같은 전위 네트워크에 속하는지를 비교합니다.

## 단자 역할

- `functional`: MCCB, EOCR, 릴레이, 타이머 등 전기적 의미가 있는 기구 단자
- `free_junction`: 사용자가 자유롭게 선택하는 TB5·TB6 중계 단자
- `external`: 전원, PB, LS, 표시등, 모터처럼 제어함 외부에 있는 전선 끝

`board.json`의 모든 핀에는 `terminal_role`을 지정합니다. 단자대 핀은 `free_junction`, 그 밖의 기구 핀은 `functional`입니다. 모든 제어함 단자의 `max_connections`는 2입니다.

외부선은 `problem.json`의 `wiring_semantics.external_devices`에 작성합니다. `operation_terminal_id`는 0.8.3 동작 정의와의 비파괴 호환 및 새 승인 결선의 동작시험 연결 변환에 사용합니다.

## 비공개 정답

`answer.json`의 `expected_nets`에는 TB 번호를 넣지 않습니다. 각 네트워크에는 함께 연결되어야 할 `functional`과 `external` 단자만 기록합니다. 한 기능 단자를 둘 이상의 네트워크에 중복해서 넣지 않습니다.

```json
{
  "net_id": "MC1_START",
  "terminals": ["MC1-4", "PB0-2", "PB1-1"]
}
```

기존 `wiring_connections`는 제작 참고와 0.8.3 데이터 호환을 위해 유지합니다. 일반 공개 API에는 `expected_nets`와 정확한 정답 전선 목록이 포함되지 않습니다.

## 판정 방식

서버는 제출 전선으로 연결 구성요소를 만든 뒤 `free_junction`을 서명에서 제거합니다. 남은 기능·외부 단자 집합이 `expected_nets`와 같으면 사용한 TB 번호와 점퍼 길이가 달라도 정답입니다.

- 필수 서명이 없으면 누락
- 서로 다른 필수 서명이 한 구성요소에 들어가면 잘못 합쳐짐
- 정답에 없는 기능 단자가 들어가면 불필요한 기능 연결
- 기능 단자가 없는 TB 연결은 고립 점퍼
- 한 구성요소의 전선 수가 단자 수 이상이면 루프

고립 점퍼와 루프 정책은 `ignore`, `warning`, `reject` 중 선택하며 기본값은 `warning`입니다. 단자당 세 번째 전선은 채점 전에 거부됩니다.

## 학습 범위

동작시험은 승인된 사용자 결선을 그대로 사용하며, 사용자가 선택한 TB 번호와 전선 색상을 보존합니다. 이 판정은 회로도 이해와 실제 결선 연습을 위한 논리 모델이며 실제 전압·전류·절연·안전을 검증하지 않습니다.
