## 실제 ZIP 이식 시험

1. 실행용 ZIP을 별도 임시 폴더에 풀었다(약 7MB).
2. 개발 `.venv`나 `node_modules`를 복사하지 않고 WebOnly 설치를 실행했다.
   이 PC에서 자동 선택된 Python 3.14 새 환경과 새로 설치한 웹 패키지로 설치 완료.
3. 검증 서버를 종료하며 만든 사용자 백업 ZIP을 새 폴더로 복사.
4. 복원 BAT의 파일 이름을 공백·한글이 있는 이름으로 바꾸고 실제 BAT를 실행, `Y` 확인.
5. 시작 BAT로 배포본 서버 실행. 기존 검증 계정 로그인 및 관리자 권한 유지 확인.
6. 이전 서버의 회로도 2/7 입력과 자유회로 작업공간 복원 확인.
7. 공개문제 도면·배관배치도·제어함 및 요구사항 확인 실행. 자유회로 템플릿 로딩 확인.

## 이식 시험에서 추가 발견한 종료 문제

최초 새 환경(Python 3.14 / Uvicorn 0.53)에서 브라우저가 연결을 끊은 뒤
Windows Proactor 소켓 종료 콜백의 `ConnectionResetError`가 발생했고,
서버가 `stopping`에 남아 백업 단계로 넘어가지 않았다. 제한시간 초과를 성공으로 처리하지 않는 점은 확인했다.
실패한 **검증 전용 프로세스만** 실행 경로·부모 PID를 확인하여 종료했고 임시 자료를 보존했다.

수정: Windows 서버는 Selector 이벤트 루프를 사용한다. 실행 중 요청 대기나
정상 종료 판정은 완화하지 않는다. 사용자 요청 취소·강제 종료로 백업을 성공 처리하지 않는다.
커스텀 루프 API가 제공되는 Uvicorn 0.36 이상을 웹 의존성에 명시했다.

수정 후 동일 Python 3.14 환경에서 HTTP keep-alive 연결을 40회 RST로 끊은 다음 종료 요청:
정상 종료 → SQLite 백업 → CRC/체크섬 검증 → 완료 ZIP 생성 성공.
수정 전 시험 ZIP은 배포 폴더에서 제외하고 최종본만 다시 생성한다.

## 제한과 인계

- 별도 물리 PC, 기관 방화벽, 실제 20명 동시 접속은 이번 작업에서 시험하지 않았다.
- 첫 설치에는 Python과 패키지 다운로드 연결이 필요하다. 완전 오프라인/무설치 EXE가 아니다.
- 복원은 병합이 아니라 지정한 백업으로 전환한다. 두 PC에서 동시에 같은 기록을 운영하지 않는다.
- 프로그램 ZIP과 개인 백업 ZIP을 구분해서 이동한다. 개인 백업은 민감한 자료이므로 안전하게 보관한다.
- 운영 방법은 프로젝트 최상위 `LAN_TRANSFER.md`에 정리했다.
