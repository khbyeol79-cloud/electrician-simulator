# 보류 작업: 외부 접속 대비 네트워크 사용량 최적화

기록일: 2026-09-22
상태: 사용자 요청으로 보류. 이 문서는 실행 지시가 아니며, 사용자가 시작을 요청한 뒤 진행한다.

## 재개할 때 사용할 요청

“외부 접속 대비 네트워크 최적화 작업 시작해줘. docs/network-optimization-backlog.md를 확인하고 진행해줘.”

## 목적과 범위

- 현재 LAN 환경에서 먼저 최적화하고, 추후 라즈베리파이 외부 접속 시에도 적용한다.
- 기능의 정확성과 저장 안정성을 유지하면서 서버 업로드량과 반복 요청을 줄인다.
- 이번 범위는 애플리케이션 전송 최적화다. 포트 개방·도메인·방화벽·외부 공개 설정은 별도 요청 전까지 변경하지 않는다.

## 진행 순서

1. Git 상태와 기존 변경사항을 확인하고 보존한다. 현재 동작과 네트워크 전송량을 측정한다.
2. 공개 도면·PDF 참고 이미지 및 버전이 구분되는 정적 파일을 재사용하도록 캐시 정책을 분리한다. 자료 갱신 시 오래된 파일이 남지 않는지 확인한다.
3. JavaScript·CSS·JSON 등 압축 효과가 있는 응답의 전송 압축을 적용·검증한다.
4. 동작시험의 반복 요청과 중복 응답을 줄인다. 시간 경과 처리, 버튼 누름·해제 순서, 타이머·플리커·인터록 정확성을 보존한다. 단순히 요청 간격만 늘려 시뮬레이션 속도가 달라지게 하지 않는다.
5. 보지 않는 탭의 불필요한 요청을 줄이고 다시 활성화되면 최신 상태를 확인한다. 동작시험을 백그라운드에서 유지할지 일시정지할지는 기존 동작과 사용자 기대를 검토한 뒤 결정한다.
6. 첫 접속, 도면 재열기, 결선 작성·저장, 동작시험의 요청 수와 실제 전송량을 전후 비교한다. 가능하면 약 20명 동시 사용 조건도 확인한다.
7. 부분 수정 → 관련 테스트 → 다음 수정 → 관련 테스트 → 마지막 전체 테스트와 실제 브라우저 확인 순서로 완료한다.

## 보존할 사항

- 자동저장 빈도를 우선적으로 낮추지 않는다. 저장 실패·재시도·종료 시 저장 동작을 보존한다.
- 사용자별 데이터 격리와 인증·권한 검사를 유지한다. 개인 결선·계정·세션 정보는 공유 캐시에 저장하지 않는다.
- 서버 끊김·복구 표시의 정확성을 유지한다.
- 기존 SQLite, 작업공간, 결선 기록, 비공개 답안은 변경·삭제하지 않는다.
- frontend/dist를 직접 편집하지 않고 src 수정 후 빌드한다.
- 절감률은 측정 전 확정하거나 보장하지 않는다.

## 사전 코드 확인 내용 (재개 시 재확인 필요)

- `frontend/src/pages/OperationTestPage.tsx`: 전원이 켜진 동작시험에서 250ms 간격 시간 진행 요청. 요청이 지연되지 않는 조건에서 1인 약 4회/초, 20인 약 80회/초이며 실제 전송량은 미측정.
- `frontend/src/pages/FreeCircuitPage.tsx`: 자유회로에도 250ms 주기 시간 진행 처리 존재.
- `frontend/src/features/system/useServerStatus.ts`: 상태 확인 간격 5초, 응답 제한 3초.
- `backend/app/core/auth_middleware.py`: 인증 모드의 API 응답에 일괄 `Cache-Control: no-store` 적용. 공개 도면 경로와 개인정보 경로를 신중히 구분해야 한다.
- `backend/app/main.py`: 정적 파일을 FileResponse로 제공. 확인 시 애플리케이션 전송 압축 설정은 없었으며 외부 프록시 설정은 조사하지 않았다.
- `frontend/src/pages/WiringPage.tsx`: 결선 변경 후 650ms 대기하여 저장. 회로도 분석은 500ms 대기하여 저장.

최신 검증 기준으로 알려진 값은 Python 605개, frontend 155개 통과이며, 작업 재개 시 현재 코드와 결과를 다시 확인한다.

이 메모 작성 시 최적화 코드·운영 서버·외부 공개 설정은 변경하지 않았다.
