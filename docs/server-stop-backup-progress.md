# 간편 서버 종료·USB 백업 및 관리자 비밀번호 재설정

기준: `320a89b`, `feature/qnet-all-wiring-capture`, 2026-09-20.

## 구현

- `서버_시작.bat`: 프로그램 위치 기준 실행, 기존 서비스 설정·관리자 저장 IP/포트 재사용. 없는 기본 설정만 최초 생성.
- `서버_종료_백업.bat`: 사용자 저장 확인 후 Y → 로컬 종료 요청 → 진행 중 HTTP 요청/앱 종료 완료 대기 → 검증된 날짜별 ZIP → 백업 폴더 열기.
- `scripts/service_lifecycle.py`: 데이터 폴더별 OS 파일 잠금, 실행 ID가 일치하는 서버만 정상 종료, 백업 중 중복 실행 차단. PID 강제 종료나 웹 종료 API 없음.
- `scripts/service_launcher.py`: 간편 실행 명령 진입점. Windows 배치 파일에서 UTF-8로 호출. 인증·단일 worker 유지.
- `scripts/run_service.py`: 환경 읽기 재사용, 기존 수동 실행과 간편 실행 사이에도 같은 데이터 폴더의 중복 실행 차단. 기존 수동 실행 자체에는 자동 종료 백업을 추가하지 않음.
- 기존 `service_data.py`의 SQLite backup API/무결성 검사를 재사용하고 ZIP CRC·manifest·SHA-256을 재확인한 뒤 완료 파일명을 게시한다. 실패 파일은 `.partial.zip`, 이전 완료 ZIP은 보존.
- 관리자 페이지의 계정별 비밀번호 재설정: 관리자 현재 비밀번호 재확인, 6~128자/확인 일치, 관리자/CSRF/동일 출처/횟수 제한, 대상 세션 전체 폐기. 대상 학습 DB는 변경하지 않음.
- 재설정 요청 검증 오류/관리 API/감사 이력에는 비밀번호 원문·해시를 노출하지 않음. 쓰기 트랜잭션 안에서 관리자 권한/해시를 다시 확인함.
- 실제 화면에서 발견한 기존 확인창 스타일 이름 누락을 고쳐 재설정·로그아웃 창이 중앙 팝업으로 표시됨.

## 부분 검증

- Python: 관리자 재설정/저장 경로/종료 백업 관련 **26개 통과**.
- 프런트엔드: 관리자 화면 **10개 통과**, 마지막 전체 **121개(17개 파일) 통과**. TypeScript 검사·운영 빌드 통과.
- 실제 격리 HTTP 서버에서 결선 저장 → 종료 요청 → ZIP 생성 → 재시작을 2회 확인. 같은 아이디로 복원본 로그인, 원본 계정 ID/관리자/가입 설정/학습 DB 보존 확인.
- 중복 시작 거부, 오래된 PID/실행 ID를 강제 종료하지 않음, 수동 실행 거부, 시간 초과·디스크 오류·손상 ZIP에서 성공으로 처리하지 않음을 검사.
- `.bat` 진입점의 도움말 실행 확인. 실제 Explorer 자동 열기와 USB 물리 복사/안전 제거는 자동 시험하지 않음.

## 실제 화면 확인

- localhost:8023 + 별도 임시 DB/시험 계정으로 관리자 로그인, 학생 계정 재설정 버튼, 대상 표시, 3개 입력칸, 확인/취소, 중앙 팝업 배치를 확인.
- UI 자동화에서는 새 비밀번호를 입력/제출하지 않고 취소했다. 실제 변경/세션 폐기/오류 처리는 위 격리 API·컴포넌트 테스트로 확인했다.
- 시험용 브라우저 탭만 닫았으며 사용자의 운영 서버·기존 비밀번호·결선 기록·Codex 앱을 종료하거나 변경하지 않았다.

## 운영 주의

- 기존 방식으로 실행 중인 서버는 저장 완료 후 해당 서버 콘솔에서 한 번 종료하고 새 시작 파일로 전환해야 한다.
- ZIP 위치: 프로그램의 `user-data-backups/`. 완료 ZIP 하나를 USB로 복사한다. 프로그램 자체/로그/인증서/env 파일은 별도 보관한다.
- 저장하지 않았거나 아직 서버로 전송되지 않은 브라우저 입력은 백업할 수 없다. 종료 전에 저장 완료를 확인한다.
- 강제 종료·정전은 정상 종료 백업을 보장하지 않는다. 완료 표시 없는 ZIP을 정상 백업으로 취급하지 않는다.
- 백업은 암호화되지 않았다. 계정 해시/개인 기록을 포함하므로 안전하게 보관한다.
- 기존 데이터 복원 절차와 LAN/HTTPS/Pi 운영 제한은 `lan-classroom-service.md`를 따른다. 실제 운영 서버를 이 작업에서 재시작하지 않았다.
