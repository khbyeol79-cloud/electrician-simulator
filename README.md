# 전기기능사 시퀀스 결선 시뮬레이터

Q-Net 공개문제 001~018로 회로도 분석, 제어함 결선, 동작시험을 연습하는 프로그램입니다. Windows 데스크톱과 웹 브라우저를 지원하며, 기관 LAN에서는 개인 계정으로 학습 기록을 구분합니다.

**공개 개발본 정리 기준일: 2026-10-01.** 화면의 제품 버전은 `0.13.0`입니다. 프로그램은 교육용 논리 동작을 확인하며, **공식 실기 정답 채점, 시험 합격 또는 실제 전기작업의 안전을 보증하지 않습니다.**

## 구현된 기능과 앞으로 할 작업

| 구분 | 내용 | 상태 |
|---|---|---|
| 회로도 분석 | 접점·코일 슬롯번호 입력, 확대·이동, 사용자별 저장 | 구현 |
| 공식 참고 자료 | 001~018의 시퀀스·배관배치·동작사항·기구 내부결선도, 선택 기구 그림 | 구현 |
| 제어함 결선 | 그래픽·요약 보기, 단자별 연결 확인, 기구 색상, PE 표시 | 구현 |
| 동작시험 | 사용자 실제 결선의 공통 엔진 실행, 문제별 요구 동작 안내·확인 | 구현 |
| 학습 저장 | 작업공간·버전·JSON 가져오기/내보내기·삭제 | 구현 |
| LAN 계정 | 아이디·비밀번호·닉네임 가입, 로그인, 계정별 데이터 분리 | 구현 |
| 운영 도구 | 관리자 화면, 비밀번호 재설정, 시작·종료 백업·복원·배포 ZIP BAT | 구현 |
| 화면·상태 | 반응형 배치, 사용법, 서버 연결 끊김·복구 표시 | 구현 |
| 네트워크 사용량 최적화 | 이미지 캐시·압축·반복 요청 감소와 전후 측정 | 보류 계획 |
| 외부 공개 | ipTIME DDNS·HTTPS·접근 보안 설정 | 보류 계획 |
| Raspberry Pi | 이전 안내·systemd 예시는 있음. 실기기 설치·운영 검증 필요 | 준비 단계 |
| Android 관리 앱·공용 포털 | 등록 기기 인증, 서버 상태 관리, 일정 공유 | 계획만 작성 |

구현은 모든 환경에서 무결점임을 뜻하지 않습니다. 약 20명·7~8시간 실제 운영, Pi 실기기 및 외부 인터넷 환경은 별도 검증이 필요합니다.

## 설치와 실행

### Windows LAN 서버

Python 3.11 이상이 필요합니다. GitHub 소스에서 프런트엔드를 빌드하려면 설치한 Vite 버전이 지원하는 Node.js를 사용합니다. 빌드 산출물과 사용자 데이터는 Git에 포함하지 않습니다.

1. `서버_최초설치.bat`으로 실행 환경을 준비합니다. 소스에서 처음 설치할 때 프런트엔드 빌드도 완료해야 합니다.
2. 운영 설정·관리자 계정·접속 주소를 [LAN 운영 안내](docs/lan-classroom-service.md)에 따라 준비합니다.
3. `서버_시작.bat`으로 시작합니다.
4. 사용자의 저장 완료를 확인하고 `서버_종료_백업.bat`으로 종료·백업합니다.
5. 다른 PC로 옮길 때는 `배포ZIP_만들기.bat`과 `백업_복원.bat`을 사용합니다. [PC 이전 안내](LAN_TRANSFER.md)를 참고합니다.

실제 계정 비밀번호를 사용하는 환경에서는 LAN이어도 신뢰할 수 있는 HTTPS가 필요합니다. 저장소를 다운로드한다고 공유기 포트나 방화벽이 자동 개방되지는 않습니다.

### Windows 데스크톱

`setup_windows.bat`으로 환경을 준비한 후 `run_desktop.bat`을 사용합니다. WebView2 Runtime이 필요합니다. Git 소스에서 화면을 처음 빌드하거나 다시 빌드하려면 `setup_windows.bat -RebuildFrontend`를 사용합니다.

## 데이터와 백업

- LAN 계정·학습 기록은 기본적으로 프로그램 폴더 안의 `user-data/`에 저장합니다.
- `user-data/`, 운영 설정 `service-config/`, 백업 `user-data-backups/`는 GitHub에 올리지 않습니다.
- 계정과 사용자 DB는 함께 백업·복원해야 기존 아이디와 기록을 유지할 수 있습니다.
- 서버 실행 중 DB 파일을 단순 복사하지 말고 정상 종료·백업 절차를 사용합니다.
- 배포 ZIP은 프로그램용이고, 사용자 데이터 백업은 별도입니다. 백업은 민감한 자료이므로 안전하게 보관합니다.

## 공개 소스 범위

기존 공개 `main`을 부모로 하여 최신 실행 코드와 공개 자료를 반영한 사본입니다. 비공개 개발 이력을 그대로 병합하지 않았습니다.

- 사용자 원문 답안, 전사·결선 JSON, 답안 재생성 스크립트 및 이에 의존하는 검수 자료/테스트는 제외했습니다.
- Q-Net 010의 비공개 후보 채점망은 공개 사본에서 제외했고, 실행에 필요한 동작 시나리오는 유지했습니다.
- 제외 목록은 [공개 소스 정책](docs/public-source-policy.json), 검증 범위는 [최신 개발 상태](DEVELOPMENT_STATUS.md)에 기록합니다.
- 공통 기구 모델, 운영 코드, 공개 PDF 참고 자료, 합성 기능 시험용 회로는 포함합니다. 옛 문서가 가리키는 비공개 자료는 공개 저장소에 없을 수 있습니다.

## 개발 검증

프런트엔드를 먼저 빌드합니다. 일부 Python 테스트에는 `frontend/dist`가 필요합니다.

```powershell
cd frontend
npm ci
npm test
npm run typecheck
npm run build
cd ..
.venv\Scripts\python.exe -X utf8 -m pytest backend/tests desktop/tests -o addopts='' -q
.venv\Scripts\python.exe -X utf8 scripts/validate_problems.py
```

문제 패키지의 `unverified` 경고는 공식 정답 미검증 상태이며 기능 구현과 구분합니다.
